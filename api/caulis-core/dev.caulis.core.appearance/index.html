Appearance
Link copied to clipboard
class Appearance

How the desktop wants programs to look: light or dark (colorScheme) and the colour buttons and selections take (accentColor). Changing it tells whoever listens (onChange): PortalSettings tells programs over D-Bus, GSettingsAppearance writes it where GTK and the GTK portal read it. All of it on the compositor's thread.

enum ColorScheme : Enum<ColorScheme>

Light or dark, as programs are told (xdg-desktop-portal's color-scheme: GTK 4, libadwaita, Qt 6, Firefox, Chromium and Electron programs follow it). DEFAULT: no wish — each program looks as it does by itself.

GSettingsAppearance
Link copied to clipboard
class GSettingsAppearance(appearance: Appearance, var gtkThemes: Pair<String, String>? = null, run: (List<String>) -> Unit = ::start) : AutoCloseable

Writes the appearance where GTK programs and the GTK and GNOME portals read it (gsettings set org.gnome.desktop.interface color-scheme prefer-dark): with xdg-desktop-portal-gtk or -gnome installed, as on most desktops, that is all programs need. GTK 3 programs follow a theme rather than the scheme: give gtkThemes (light, dark), e.g. ("Adwaita", "Adwaita-dark"), and the theme changes too. Nothing is written until the appearance changes. Close it to stop.

PortalSettings
Link copied to clipboard
class PortalSettings(bus: DBusConnection, appearance: Appearance, val busName: String = BUS_NAME) : AutoCloseable

Tells programs the appearance the way xdg-desktop-portal asks its backends (org.freedesktop.impl.portal.Settings: org.freedesktop.appearance color-scheme, accent-color, contrast), on the session bus under busName, and again whenever it changes. The portal uses it where it is told to (a caulis.portal file and a <desktop>-portals.conf line: see the guide); close it to stop.
