MovingArea

data class MovingArea @JvmOverloads constructor(val x: Double, val y: Double, val width: Double, val height: Double, val restFps: Int = 0, val burstEvery: Double = 0.0, val burstFor: Double = 0.0, val quietArea: MovingArea? = null, val keptSeconds: Double = 600.0, val settleSeconds: Double = 0.3, val maxKeptSize: Double = 2.0)

The only part of a WallpaperShader's picture that changes, as fractions of the picture (x, y its top left, width, height its size, all 0..1 like at): the whole picture is drawn once into a picture kept on the GPU (one as big as the shader's place, 4 bytes a pixel: 9 MB for 1920x1200, again when its size, colours or values change), and each of its frames draws only this part anew into that and shows it. What it costs per frame is the cost of this part.

What the shader must do in return: outside this part its picture must not depend on time or the pointer, or the edge shows. For that it can read:

  • float movingFade(vec2 at, float width) — 1 well inside the part, falling to exactly 0 at its edge and beyond over width (a fraction of the picture's height); 1 everywhere with no area declared. Multiply what moves by it.

  • bool movingDeclared — an area is declared (else the shader is drawn whole every frame).

  • bool movingWhole — this drawing must give every pixel it is asked for (the first one). When false, a pixel that did not change since float movingSince (the time of the last drawing) can be left out with discard, and costs only the check: it keeps its colour. (After you read dFdx or dFdy: a pixel beside one thrown away earlier gets a wrong slope.)

restFps, burstEvery and burstFor spare frames too: while the pointer rests and no burst goes on it is drawn only restFps times a second (0: as fast as its framesPerSecond), for something slow; every burstEvery seconds of time it goes at full pace for burstFor seconds (a blink, 0: never). quietArea, inside this one, is all that changes outside bursts (the eye without its lids): then only that is drawn anew; a burst, and a frame or two after it, draws all of this one.

What is kept costs GPU memory, so these three say how much and how long: keptSeconds, how long a kept picture nothing draws (a fullscreen window over it, another wallpaper) stays, at least a second; drawing it again costs one full frame. settleSeconds, how long a new size must stand still before the picture is drawn again at it (a zooming view stretches the old one meanwhile). maxKeptSize, the most it is of the monitor's pixels each way (a view zoomed in further stretches it): 4 bytes a pixel.
