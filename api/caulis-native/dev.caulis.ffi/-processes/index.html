Processes

object Processes

The one way Caulis — and a compositor built on it — starts programs: start takes a ProcessBuilder as it is (command, directory, environment, where input and output go) and gives back an ordinary Process.

Java starts programs through a helper program of its own (jspawnhelper). When the system updates Java while the compositor runs, the new helper no longer fits the running Java and every start fails until the compositor is restarted ("Failed to exec spawn helper ... JDK version mismatch"). So by default (Method.NATIVE) programs are started directly with the C library's posix_spawn: nothing of Java's installation is needed. Only the program's standard input, output and error go along (none of the compositor's other open files), it starts with no signal blocked, and every signal at its default.

Method.JAVA uses ProcessBuilder.start() — and when that fails with the helper's error, the start is tried again natively, and natively from then on.
