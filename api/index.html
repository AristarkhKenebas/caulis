caulis-compose
Link copied to clipboard

Parts of a compositor's own interface written in Compose — a bar, a dock, a launcher, a volume pill, notifications. Each is a Compose scene drawn into a picture (no window, no X11) and shown by the compositor as one of its widgets: it gets the pointer where it is, the wheel, and — when it asks — the keyboard (text fields work, with the keyboard layout). Everything Compose runs (recomposition, animations, LaunchedEffect) runs on the compositor's thread.

caulis-core
Link copied to clipboard

The compositor itself: surfaces and windows, the window manager (dev.caulis.core.Desktop), input, monitors, and the two backends (a window in another session, or the real screen). Use it directly when caulis-wm is not flexible enough.

caulis-cursor
Link copied to clipboard

Cursor themes: reading XCursor files (dev.caulis.core.cursor.XCursor), finding a theme the way other programs do (the user's and the system's icon folders, XCURSOR_PATH), and Caulis's own themes ("Caulis", "Caulis-Black") inside the jar. A library can bring more themes (dev.caulis.core.cursor.CursorThemeProvider). caulis-core brings it; it needs nothing else.

caulis-dbus
Link copied to clipboard

D-Bus, the message bus of the desktop, spoken directly over its socket on Caulis's event loop (no libdbus): method calls and their replies, signals, objects of your own on the bus, file descriptors passed along. caulis-core brings it; it needs only caulis-native.

caulis-geometry
Link copied to clipboard

Rectangles in whole pixels (dev.caulis.geometry.Rect), shared by drawing and tiling.

caulis-ipc
Link copied to clipboard

The IPC socket of a running compositor: its messages, described in src/main/proto/caulis/ipc/v1/caulis.proto (programs in any language make their code from it), and dev.caulis.ipc.CaulisIpc, a client for programs on the JVM. The compositor's side is part of caulis-wm.

caulis-log
Link copied to clipboard

The log of Caulis: levels 0 (nearly silent) to 3 (everything, step by step), for everything or for single areas (wayland, focus, render, ...). See dev.caulis.log.Log.

caulis-lua
Link copied to clipboard

config.lua: a compositor's configuration in Lua (LuaJ, Lua 5.2 on the JVM). A compositor with this module on its class path reads config.lua from its folder by itself. See the guide, step 27.

caulis-native
Link copied to clipboard

Safe Kotlin around the C pieces Caulis needs: file descriptors, sockets, shared memory, epoll — and the event loop (dev.caulis.event.EventLoop) everything runs on.

caulis-protocol
Link copied to clipboard

The Wayland protocol, implemented from scratch: the wire format, the server side (dev.caulis.protocol.Display, clients, objects) and a client side. Classes for each protocol are generated from its XML description.

caulis-reload
Link copied to clipboard

Fast hot reload, for development only: when you save a file, your configuration is compiled right inside the running compositor (the Kotlin compiler, and the JDK's own for Java files) instead of a Gradle build, incrementally (only what changed, and what depends on it) — well under a second from saving to seeing it. Without this module, hot reload uses the project's Gradle and takes several seconds.

caulis-render
Link copied to clipboard

Drawing on the GPU. The rest of Caulis only talks to dev.caulis.render.Renderer, so the technology behind it can change (OpenGL ES today, Vulkan later).

caulis-screenshot
Link copied to clipboard

Screenshots inside a Caulis compositor: the screen frozen at once, a toolbar to choose an area, a window or a monitor (with or without the pointer, at once or after a few seconds), saved as PNG or JPEG and put on the clipboard. Optional: screenshots() in a configuration binds Print, Shift+Print and Alt+Print; with this module on the class path, text configurations have the screenshot action. See the guide, step 20.

caulis-script
Link copied to clipboard

config.kts: a compositor's configuration as a Kotlin script, compiled by the compositor itself — no Gradle, no project. A compositor with this module on its class path reads config.kts from its folder by itself. It contains the Kotlin compiler. See the guide, step 28.

caulis-xwayland
Link copied to clipboard

X11 programs in a Caulis compositor: Xwayland is started when the first one connects, and Caulis is the window manager of their windows (through XCB) — they tile, float, get title bars and effects, show in docks and screen sharing like Wayland windows, at the right scale. Copy and paste works between X11 and Wayland programs (CLIPBOARD, large data in pieces).
