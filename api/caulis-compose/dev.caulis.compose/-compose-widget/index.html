A part of the compositor's own interface written in Compose — a bar, a dock, a launcher, a volume pill: a Widget whose content is a Compose scene (one per monitor it is on), drawn into a picture only when something in it changed, and getting the pointer (with the shape Compose asks for), the wheel and — with takesKeyboard — the keyboard (text fields work, Ctrl+C and Ctrl+V with the compositor's clipboard).

desktop.addWidget(ComposeWidget(desktop, post = { loop.post(it::run) },
    place = { m -> Rect(m.area.x, m.area.y, m.area.width, 32) }, reserve = { Reserve(Edge.TOP, 32) }) { monitor ->
    Row(Modifier.fillMaxSize().background(Color(0xCC1E1E2E))) { Text(monitor.name, color = Color.White) }
})

Close the widget (or the handle Desktop.addWidget gave: that closes it too) when it is not needed any more: it is then nowhere (no room kept, no clicks taken, nothing drawn). A new size in pixels (its area grown, another scale) makes its scene anew: state kept in it with remember starts over then — keep it outside for a widget that changes its size, or give it a sceneSize. In a Caulis configuration compose(...) does this for you.

Everything Compose runs (recomposition, animations, LaunchedEffect) runs on the compositor's thread through post; call its functions on that thread too. Content that throws is logged and started over (recovery); while its appearance is fully see-through it is not drawn at all.

prewarm
Link copied to clipboard
fun prewarm(monitor: Monitor, width: Int, height: Int)

Draws its scene once now, off screen, width x height units on monitor. The first time something is drawn is slow (classes loaded, fonts, pictures): done ahead, its first showing is as quick as the next ones. Its own scene is kept when that is its size (with a sceneSize, the scene is that size and width, height do not matter). Nothing once it is closed. Call it on the compositor's thread.
