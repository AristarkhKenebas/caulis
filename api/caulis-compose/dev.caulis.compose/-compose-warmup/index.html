ComposeWarmup

object ComposeWarmup

Compose made ready on a thread of its own, before the compositor's thread needs it.

The first Compose scene (a bar) took ~0.7 s of the compositor's thread — Compose's classes loaded and set up, Skia's fonts found, its code still slow — and meanwhile no input was handled and no frame drawn: the pointer stood still. start draws a small scene of common parts (rows, columns, text, shapes, shadows, a list) a few times on another thread, at the same time as the compositor starts: that cost is then paid on another core.

content, if given, is drawn instead: it runs on that other thread, so it must not touch the compositor or anything of yours that is not safe from two threads — layout and drawing only (no effects that do something: they are not run).

fun draw(width: Int, height: Int, frames: Int = 2, content: @Composable () -> Unit)

Draws content times in a scene of width x height pixels on the calling thread (not the compositor's: that is the point), then forgets it — for a compositor that draws its own menus ahead one after another on a thread of its own. The same rules as for start's content: layout and drawing only; coroutines its effects start run on this thread between the frames. What content throws is passed on.
